검토할 이슈 제목

해결한 문제와 현재 가능한 동작을 한 문단으로 설명한다.

작성 시점 상태: 구현/검증, commit/push, PR merge, GitHub 종료 여부를 실제 근거대로 각각 적는다.
이슈번호와 링크브랜치작업 브랜치
코드 기준commit 또는 미커밋기록 시점실제 실행일/보고서 기준일

1. 목적과 구현

변경 전 문제, 구현한 동작, 주요 변경 파일과 기존 구조의 연결을 쓴다.

2. 수락 기준별 확인

수락 기준구현·검증 근거판정
실제 이슈의 기준파일·명령·관측한 결과완료 / 부분 / 미실행

3. 검증 결과

실제 환경 실행, mock/scripted 검사, 미실행을 구분한다. 명령·일자·성공/실패 수·종료 코드·시간·비용을 근거 범위 안에서 적는다.

4. 실패·수정·남은 제한

처음의 실패도 남기고 수정 이유와 재검증을 적는다. 검증하지 않은 기능·환경, 잔여 문제와 다음 작업을 명시한다.

5. 검토 근거

PROGRESS.md, 검토 문서, raw artifact, 관련 코드와 GitHub 이슈/PR 경로를 기록한다.

필요하면 새 section에 class="page"를 지정한다. 템플릿 문구를 실제 내용으로 교체한 뒤 PDF로 출력한다.
