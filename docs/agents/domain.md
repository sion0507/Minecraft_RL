# Domain Docs

## Layout

This repo uses a single-context layout:

- `GLOSSARY.md` at the repo root: domain terminology.
- `docs/adr/`: architecture decision records.

## Before exploring

Read the glossary and ADRs relevant to the work.
If they do not exist, proceed silently without suggesting creation.
Domain-modeling skills create them when terms or decisions are resolved.

## Vocabulary

Use glossary terms consistently in issues, proposals, and tests.
If a needed concept is missing, reconsider the wording or note the gap
for domain modeling.

## ADR conflicts

Explicitly identify any proposal that contradicts an existing ADR,
including the ADR number and why the decision should be reconsidered.
