# Issue 14: 사건 보상과 시간 할인 PPO 구현 계획

> **For agentic workers:** Use superpowers:executing-plans inline. Review the completed change with code-review.

**Goal:** 기존 공개 에피소드 흐름의 직접 사건을 local/full 보상·저장 전이·GAE·NanoJev PPO 업데이트에 연결한다.

**Architecture:** 공통 실행기는 선택적으로 학습 관찰자를 받는다. 보상 ledger는 표준 라이브러리로 구현하고 PPO는 기존 NanoJev의 frozen encoding/evaluate_actions를 재사용한다. smoke-ppo는 짧은 진단이며 본 학습·커리큘럼·복구 저장은 후속 티켓이다.

**Tech Stack:** Python, 기존 PyTorch/Pydantic/PyYAML, 기존 mock JSONL RPC.

**Spec:** GitHub #14/#1 본문·댓글, PLAN §§6.2/8.1/12/13 Task 8. 사용자 implement 요청으로 현재 main에서 구현·커밋한다.

## Global Constraints

- 기존 관측/후보/목표/실행기를 재사용하고 제공 아이템·불완전 경험을 보상/학습 성과로 세지 않는다.
- Choice LR/value LR 1e-4, clip .2, lambda .95, entropy .01, value coefficient .5, grad norm .5, rollout 128, minibatch 32, epochs 4.
- 단일/0후보·취소·fallback·critic-only는 actor 제외. Jev/S 경험은 PPO에 넣지 않는다.
- 공개 CLI 흐름과 손계산 가능한 공개 보상/GAE/actor-critic 계약이 사전 합의된 검사 경계다.
- PDF 두 개만 reports에 로컬 저장한다. push/merge/이슈 종료는 이번 요청에 없다.

## Review Focus

- full 목표 변경과 rollout/운영 절단에서 정확한 다음 목표/후보로 bootstrap한다.
