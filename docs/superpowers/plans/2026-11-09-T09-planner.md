# T09 공통 계획기 연결 구현 계획

**Goal:** #10의 실제 고정 4비트 Qwen 및 핵심 F Astra 연결을 기존 목표 처리 흐름에 연결한다.
**Spec:** GitHub #10·#1 본문/댓글, PLAN §5.1·5.5·5.6·7.4·14.
**Architecture:** 기존 Planning의 검증/한 번 재생성/복구와 run_episode를 재사용한다. 두 backend는 같은 직접 작성한 프롬프트·제한 입력을 받는다. scripted backend는 기존 테스트와 호환한다.
**Tech Stack:** 기존 Python/uv/Torch/Transformers, 4비트 bitsandbytes·accelerate, HTTP 표준 라이브러리.

## 범위와 경계

- 수정: schema의 계획기 설정, goals.Planning, episode/cli 호출부. 추가: planner backend, 고정 프롬프트, smoke 설정·공개 CLI 테스트.
- 테스트 경계는 #1 Testing Decisions와 #9에서 승인된 공개 CLI reset→관측→목표→후보→실행→출처별 요약, 공통 Planner 입출력이다. 실제 모델·게임·과금은 mock과 구분한다.
- 기존 설정/고정 목표/평가 슬롯을 보존한다. 정보 경계를 변경하지 않는다. bridge·snapshot은 변경하지 않는다.
- 현재 브랜치 커밋은 implement의 명시적 요청이다. push/merge/이슈 종료는 하지 않는다.
- Astra 제공처/모델/지원 설정/승인·상한 미확정은 질문 중이다. 유료 호출은 답변과 승인 전 실행하지 않는다. 미확인 연결을 성공 처리하지 않는다.
- 7B 학습·6상태 비교·PPO·전체 C4/G4는 이 티켓에서 실행하지 않는다.

## Review Focus

제공처 실패와 잘못된 목표를 구분한다. 재생성/복구의 출처와 비용을 보존한다. 저장된 관측 외 정보와 후보 선택 권한을 주지 않는다. 모든 유료 시도·실패·재시도가 영속 상한을 소비한다. 모델/프롬프트/file hash가 실제 실행과 일치해야 한다.
