## Standards

확정된 문서 규칙 위반과 보고할 수준의 코드 냄새가 없다. 연료 미확인 시 후속
철 투입을 차단하고 실패 사건과 철3 보존을 확인하는 회귀를 검토했다.

입력 순서 보완 재검토에서도 추가 확정 지적이 없다. 관리자 권한·플레이어 식별·
nonce/동결/중복 검증, 이동 이후 동일 서버 실행기에 예약하는 순서, 전송 실패와
연결 종료의 listener 정리를 확인했다. 패킷 버퍼는 handler 반환 뒤 vanilla가
해제하며 executor에는 복사한 문자열만 전달한다.

## Spec

첫 재개 검토에서 P2를 지적했다. 명세의 “해당 틱의 서버 변경이 클라이언트
상태에 반영된 뒤 관측” 조건에 대해, 기존 advance는 receipt 뒤에도 늦은 물리를
허용했고 MovementPause가 이동을 다음 활성 틱까지 보류할 수 있었다.
기존 late_physics fixture의 빈 pause는 이 위치 불일치를 잡지 못했다.

영구 dispatch 회귀에 서버 입력/위치 큐를 모델링해 RED를 확인한 뒤,
물리 완료→같은 TCP연결 nonce echo→서버 실행기 확인→활성 틱→상태 전송 순서로
수정했다. 재검토에서 기존 P2 해결과 잔여 확정 지적0을 확인했다.
플레이어·nonce·동결 검증과 관리자/정책 채널 분리도 유지된다.
